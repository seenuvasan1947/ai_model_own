# Version 3 (in progress): foundations first — numbers and maths learned, wrong answers removed

Branch `hebbian-v3`, cut from `hebbian-v2` / `release-v1.0.0` (commit `fdf9e53`), which are untouched. The plan, as agreed: teach the
foundations in school order and test each stage. **Done here: the wrong-relation fix and stages 1–2 (number sense and arithmetic).**
Stages 3–5 (core word meanings, grammar rules, restating in its own words) are not started.

## 1. Fix: an understood question with no answer says "i do not know"

In v2, when a question was understood but nothing was stored, the language layer's diffuse knowledge was used as a fallback, which
could answer a different relation ("what color is the lion ?" -> "the lion says roar"). That fallback is now used only for
questions the rules could not read at all. A test covers it.

## 2. Learned number sense (`numbers.py`)

Counting and arithmetic are no longer a built-in rule that is simply looked up. They are learned the way a child learns them:

| Step | What is learned | How |
|---|---|---|
| Counting | digit-to-digit *successor* synapses (`w[a, b]`: after digit `a` comes `b`) and *carry* links (when a digit wrapped, the next place changed too); the same for counting backwards | every neighbouring pair in a counting run ("zero one two ...", "10 11 12", "ten comes after nine") strengthens the links (Hebbian, asymmetric) |
| Counting any number | nothing more | the digit links are shared by all places, so counting to a hundred gives the next number of anything (12,345 -> 12,346) |
| Order | the order of the digits, read off the learned successor chain | "which is bigger", "is 12 more than 7" |
| Adding | nothing more: **counting on** from the larger number | uses only successor |
| Subtracting | counting back (predecessor) | |
| Multiplying / dividing | repeated adding / repeated subtracting (division gives a remainder) | |
| Practice | each worked-out sum leaves a trace; worked out (or taught: "seven plus eight is fifteen .") twice, it is *recalled* instead of counted; traces fade with time and the skill falls back to counting | strengthening + decay, as for facts |
| Being taught something wrong | "two plus two is five ." is checked by counting; the counting wins and it says "that does not match my counting" | |

Given as vocabulary, not learned: the words for numbers ("twenty seven" = 27) and the fact that numerals are written in places
(positional notation). Everything built on the successor links is learned. Before it has learned to count it still answers
arithmetic questions with the old rule, and says so ("by rule : i have not learned to count yet").

`Workspace.school(count_to=100, repeats=3)` does the schooling (count to 100 three times, practise the tables); `train.py` does it before
saving the workspace. New question forms: `what is 27 + 15`, `... divided by ...`, `what comes after / before 39`, `count from 3 to 8`,
`which is bigger , 7 or 12`, `is 12 more than 7`. New teaching forms: a counting run, `four comes after three .`, `two plus three is five .`.

## 3. Measured (`python train.py`, benchmark J; the answer key is Python arithmetic, used only for scoring)

| Counting taught to | next number, numbers it was shown | next number, unseen (up to 2000) |
|---|---|---|
| 0–9 | 1.00 | **0.90** (it fails exactly on numbers ending in 9: it never saw 9 -> 10, and says so) |
| 0–19, 0–39, 0–100 (once or three times) | 1.00 | **1.00** |

* After school (count to 100 x3, small tables), 200 random problems per operation, asked as questions: plus 1.00, minus 1.00, times 1.00,
  divided by 1.00 (with remainder). **This is exact because the operation is built from correct successor links**, so it shows the links
  were learned correctly, not that arithmetic was learned approximately. It cannot make a calculation error that counting would not.
* Mean counting steps per two-digit sum when the same sum is asked 1st / 2nd / 3rd / 4th time: **36.6 / 36.6 / 0 / 0**: practice turns
  counting into recall.
* Taught as a statement k times ("a plus b is c ." for 100 small sums): share recalled from memory afterwards: k=0: 0, k=1: 0, k=2+: 1.00.
* A wrong claim taught ten times does not change the answer.
* Counted only to 9: `3 plus 4` is seven, `8 plus 9` -> "i have not learned what comes after 9 yet . i can count to nine so far ."

## 4. What this does not do

* It counts; it has no column-addition procedure, so big sums take many steps (more than 20,000 steps it declines) and
  `987654 + 123456` is refused. Multiplication of large numbers is slow for the same reason.
* No negative numbers, fractions or decimals; no word problems ("Tom has 3 apples and gets 4 more"); numbers are not yet joined to the
  fact memory (counts such as "the shop has 312 books" still work as before but are not added up).
* The word for a number and the positional notation are given. The learner is shown counting runs; it does not discover numbers from
  raw experience.
* The workspace in `release/v1.0/` was trained before this stage and has no number sense; run `python train.py` (about a minute) to
  build one with it, or `Workspace.school()` on your own workspace.
